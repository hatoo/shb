# HTTP/2 pending-flush bitmap (c90, 2026-10-10)

After each completion batch, the worker previously searched every connection
object for `needs_flush`. The bitmap keeps one bit per slot, coalesces repeated
marks, and drains in the original connection-index order. Fully marked words
use a sequential loop. Reconnects retain the slot's mark; stale completions
remain filtered before marking. Sends, request accounting and timestamps are
unchanged. The optional `--timeout` scan is also unchanged.

The accepted scope is the tested high-connection workloads below. These results
do not establish a general HTTP/2 gain or equivalence in other configurations.

## Build and measurement

Baseline shb `add4c976c7f7335089d55d7defec1f7228daf154`; fixed hfast
`30b137401746eab4fc9670550e143ce313e489b2`. Both immutable shb executables used
rustc 1.98.0, the default release profile (fat LTO, one codegen unit) and mimalloc.
WSL2 kernel 6.18.40.1; client CPU 2, hfast CPU 0, gate CPU 4 (separate physical cores).
Three alternating pairs followed by three independently reversed pairs; warmup
runs precede measurement. All final counted runs had exact success/status counts,
zero errors and latency reports. Audited runs additionally checked exact sample
counts. Small WSL timing differences remain inconclusive; no A/A retry or affinity
sweep was used.

## Sparse responses, fixed hfast

The transparent gate first collects one response per connection. It releases the
active connections, holds the other first responses, then delivers every held
response after the active connections consume the remaining request budget.
All responses are generated by the same hfast. No bytes are rewritten or dropped.
There are 32,768 requests with one active connection and 65,536 with eight.

The release interval starts after connection setup and ends when shb exits.
**Only this scoped interval excludes setup.** Client CPU covers the complete
process; CLI reports and all latency samples also retain setup. The complete
process wall time was more variable and is not the accepted elapsed-time claim.
Every one of six measured pairs per case reduced the release interval and CPU.

| Workload | Release time, primary / reversed | Complete client CPU, primary / reversed |
|---|---:|---:|
| 16,384 connections, 1 active | -14.629% / -12.804% | -31.391% / -32.644% |
| 16,384 connections, 8 active | -15.464% / -11.833% | -30.928% / -35.225% |

There were 1,179,648 measured sparse successes plus 393,216 warmup successes.
Connection timeout is 30s in both variants: the original 5s limit was insufficient
for 16,384 proxy connections. Request timeout is off. A failed original warmup
also exposed missing reset handling in the fixture; it now accepts resets only
after all upstream responses exist and still requires an exact, zero-error
client report. Early resets fail. No measured confirmation pair was repeated;
a fresh warmup series followed the fixture repair. No reset exception occurred
in the accepted confirmation series. The original reset cause remains undetermined.

Reproduce with immutable binaries and a new output directory:

```sh
python3 benchmarks/compare-h2-flush.py \
  --baseline /path/to/shb-baseline --candidate /path/to/shb-candidate \
  --server /path/to/fixed-hfast --out /tmp/h2-flush-primary --phase primary
python3 benchmarks/compare-h2-flush.py \
  --baseline /path/to/shb-baseline --candidate /path/to/shb-candidate \
  --server /path/to/fixed-hfast --out /tmp/h2-flush-confirmation --phase confirmation
```

The script records binary hashes, arguments, raw reports, counts and individual
paired changes. It requires Linux, Python 3, taskset, and sufficient descriptors
for four sockets per proxied connection. `--case C:A:N` selects a smaller smoke
workload. Existing evidence is never overwritten.

Use one hfast TCP worker, no QUIC listener, and pin shb to CPU 2:

```sh
hfast --tcp 28090 --quic 0 --threads 1
taskset -c 2 shb -j --http2 -t 1 -c 4096 -p 1 -n 8192 http://127.0.0.1:28090/
taskset -c 2 shb -j --http2 -t 1 -c 4096 -p 1 -n 1048576 http://127.0.0.1:28090/
```

Alternate the immutable binaries after each warmup. Other measured request counts:
1/p1: 32,768; 1/p128 and 128/p1: 1,048,576; 16384/p1: 2,097,152; 16/p64: 4,194,304.
Warmup is max(8192, 2 * connections). The ordinary matrix completed 113,639,424
measured and 884,736 warmup successes with no errors.

## Costs and correctness

Scheduling is O(ceil(connections/64)+dirty); no complete connection-object scan
or hot allocation is required. On this build, Conn shrinks from 1,424 to 1,416 bytes.
At 16,384 connections, the bitmap adds one 2,048-byte allocation while connection
storage falls by 131,072 bytes: net requested heap decreases by 129,024 bytes,
with one extra 24-byte worker Vec.
Allocator rounding/RSS is not inferred from requested sizes.

Scheduler-only replay uses production marking/draining and actual Conn layout,
with the same observer replacing I/O. With 16,384 connections and one dirty slot,
instructions per batch fall from 98,352 to 2,892 (-97.060%), and CPU falls by about
99.6% in both five-pair series. Costs remain: singleton instructions rise from
54 to 87; fully dirty 16,384 takes 14.846% more instructions; dense 128 ordered
CPU increases 47.45%/48.35%, and dense 4096 ordered CPU increases 12.19%/8.61%.
These are isolated scheduling costs, not whole-worker throughput claims.
An initial first-completion-order list was rejected after all six 16384/p1 socket
pairs slowed down; the bitmap preserves the original ordering and uses less memory.

Validation: 332 unit tests passed and 53 integration tests passed in debug and
release (two pre-existing ignored tests); 53 HTTP/2 tests passed on Rust 1.91;
fmt and strict all-target Clippy passed. Five new ring/bitmap tests cover duplicate
marks, close/reconnect generations, in-flight buffers, sparse boundaries and full
word ordering. New TCP/TLS GOAWAY tests cover concurrent reconnects. Independent
hfast/Caddy audits preserve exact samples/statuses for successes, deadline runs
and refusals. Forced backpressure produced 19 partial Sends while all 64 large
request-header responses completed correctly.
